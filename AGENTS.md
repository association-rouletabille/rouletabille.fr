# AI Agent Guide — rouletabille.fr

Static site (Eleventy 3.x / WebC) + Cloudflare Worker. Node 24.x required.

## Commands

| Command             | Purpose                                                                |
| ------------------- | ---------------------------------------------------------------------- |
| `npm run build:dev` | Build site → `dist/` — **cross-platform; use for all agent workflows** |
| `npm run clean`     | Delete `dist/` (safe; uses rimraf)                                     |
| `npm run serve`     | Dev server at http://localhost:8080 with hot reload                    |
| `npm run lint`      | ESLint with auto-fix                                                   |
| `npm run format`    | Prettier                                                               |

> **`build:dist` is bash-only** (injects real git SHA via `$()`) — never use in agent workflows.

## Project Structure

```
src/
  *.webc               — Pages (filename = route slug, e.g. adhesion.webc → /adhesion)
  _layouts/
    root.webc          — HTML shell (doctype, <head>, CSS bundle link, JSON-LD)
    base.webc          — Page wrapper (header + main + footer); used by all pages
  _includes/webc/      — Reusable WebC components (globally registered by name)
  _data/site.js        — Global site data: URL helpers, JSON-LD schema
  assets/              — Icon SVGs (sprite auto-generated at build time)
  public/              — Pass-through to site root (robots.txt, llms.txt, …)
  worker.ts            — Cloudflare Worker (API routes + scheduled crons)
dist/                  — Build output (gitignored)
wrangler.jsonc         — Worker config: cron triggers, assets directory, custom domain
eleventy.config.js     — Eleventy: plugins, CSS/HTML minification, global data
```

## Adding a Page

1. Create `src/[slug].webc` (or `src/[slug]/index.webc`)
2. Frontmatter: `layout: base.webc`, `title:`, `description:`
3. Body: wrap content in `<article>` with `<section>` blocks
4. Nav: add `<li><a href="/[slug]">Title</a></li>` in `src/_includes/webc/header.webc`; prepend `class="nav-section-start"` to add a separator
5. Verify: `npm run build:dev` (exit 0 = success)

## Adding a Component

1. Create `src/_includes/webc/[name].webc`
2. Style with `<style webc:scoped>` — use `:host` to target the component element
3. Use by tag name `<name>` in any layout or page — auto-registered, no imports needed
4. Verify: `npm run build:dev` (exit 0 = success)

## WebC Patterns

- CSS lives inside `.webc` files — bundled + minified by Lightning CSS; no separate `.css` files
- CSS syntax: `<style webc:scoped>` in components (use `:host` selectors); plain `<style>` in pages for unscoped page-specific styles
- Components in `src/_includes/webc/` are globally registered; use by tag name (e.g. `<icon>`)
- `webc:scoped` — scoped component styles; `@raw` — raw HTML output; `@text` — text node binding; `:attr` — attribute binding
- No client-side JavaScript by default — pure static HTML
- Global data helpers: `getBundleFileUrl('css')`, `getSvgSpriteUrl()`, `$data.site.jsonLd()`

## Cloudflare Worker (`src/worker.ts`)

- **GET /api/latest-posts** — Instagram feed (cached 2 h in KV)
- **Cron every 30 min** — Refresh Instagram posts from Graph API into KV
- **Cron Monday 3 am UTC** — Refresh Instagram access token if near expiry
- `INSTAGRAM_KV` binding is optional; crons skip gracefully if absent
- TypeScript strict mode; Worker types auto-generated by `wrangler types`

## Key Constraints

- **Pre-commit**: lint-staged runs ESLint + Prettier automatically via Husky
- **`COMMIT_SHA` fallback**: agents see `deadbeef` in `<meta name="version">` — harmless
- **Playwright**: not installed as a dep; use `npx playwright open http://localhost:8080` ad-hoc
